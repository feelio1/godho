스프린트 8 지시서 — 펫병원체크 지정 병원 + 반려동물 건강기록(로컬 최소)

목표: (1) 홈에 "지정(단골) 병원" 바로가기 + 전화, (2) 반려동물 건강기록 무료 로컬 최소 버전. 기존 검색/지도/타임라인 로직은 변경 금지. CLAUDE.md 원칙·워딩·중립성 준수. Riverpod 유지.
중요: 이번엔 로컬 저장(기기 내)만. 서버·계정·결제·Firebase 없음. 다음 단계 Firebase 이관을 대비해 Pet/MedicalRecord를 순수 클래스 + JSON 직렬화로 분리해 둠.

1. 홈: 지정(단골) 병원 바로가기

* 홈 상단(마스코트 인사 바로 아래)에 "지정 병원" 섹션. `designatedHospitalsProvider`(로컬 id 배열, `LocalStore.toggleDesignated`)로 관리하며, 기존 "저장(♡)"과는 완전히 별개 목록이다.
* 지정 방법: 상세 화면 헤더에 하트(저장) 옆 압정 아이콘(`Icons.push_pin`)으로 등록/해제.
* 지정 병원 카드(`DesignatedHospitalCard`)에서 바로 전화(`ExternalLinks.call`)·길찾기(`ExternalLinks.openDirections`)·상세보기 가능.
* 영업시간·실시간 영업여부는 표시하지 않음 — 상세의 기존 외부 링크(카카오맵/네이버)로 안내.

2. 반려동물 건강기록 (로컬 최소 버전)

* 하단 탭을 늘리지 않고 홈의 "우리 아이 건강기록" 카드(`_HealthRecordEntryCard`)에서 별도 화면(`HealthRecordScreen`)으로 진입 — CLAUDE.md 하단 탭 3개 원칙과 "정보구조 과밀 주의"를 함께 지킴.
* 반려동물 프로필(`Pet`): 이름, 종(개/고양이/기타), 품종(선택), 생일(선택), 사진(선택, 갤러리에서 선택 — `image_picker`). 지금은 1마리만 화면에 노출하지만 저장 구조(`List<Pet>`)는 여러 마리를 담을 수 있다.
* 진료/방문 기록(`MedicalRecord`): 날짜, 병원(우리 DB 검색·선택 또는 직접 입력 — `hospitalId`는 선택된 경우에만 채워짐), 메모, 몸무게(kg, 선택), 진료비(원, 선택), 사진(선택). 최신순 리스트, 편집·삭제 가능.
* 최소 요약: 기록 개수, 총 진료비 합계, 최근 몸무게만 텍스트로 — 그래프·통계 없음.
* 빈 상태는 `MascotMessage` + "반려동물 등록하기" 버튼.

3. 데이터 저장·안내

* `LocalStore`에 `pets_json_v1`/`medical_records_json_v1`(JSON 배열 문자열)로 저장. `Pet`/`MedicalRecord` 모델은 저장 방식과 무관한 순수 클래스 + `toJson`/`fromJson`만 가짐 — 후속 Firebase 이관 시 `LocalStore`의 두 메서드 쌍만 원격 호출로 바꾸면 된다.
* `HealthRecordScreen`에 "이 기록은 현재 기기에만 저장됩니다. 앱 삭제/기기 변경 시 사라질 수 있습니다." 고지 문구 고정 표기.
* 사진은 `image_picker`로 고른 파일의 로컬 경로 문자열만 저장(용량 절감을 위해 `maxWidth`/`imageQuality`로 압축). 갤러리 선택만 지원(카메라 촬영은 이번 범위 아님 — 매니페스트 권한 최소화).

건강·안전 원칙

* 몸무게·진료비는 기록으로만 보여주고 "비만/정상" 같은 판정 문구를 어디에도 넣지 않음. 요약 텍스트도 숫자 나열뿐이며 해석·조언이 필요하면 화면 밖에서 수의사와 상담하도록 자연스럽게 유도(별도 경고 문구를 남발하지 않음 — CLAUDE.md 평가 금지 원칙의 연장).

하지 말 것 (준수 확인)

* 서버·계정·로그인·결제·Firebase 도입 — 전부 `SharedPreferences` 로컬 저장뿐, 네트워크 호출 없음.
* 그래프·통계·PDF 내보내기·여러 마리 고급 UI — 텍스트 요약 3개 항목만 구현.
* 건강 데이터 기반 진단/조언/평가 — 없음.
* 검색/지도/타임라인/병합 로직 변경 — 미변경(신규 파일 + `home_screen.dart`/`detail_screen.dart`에 진입점만 추가).
* 실시간 영업여부·영업시간 표기 — 없음.

## 구현 메모

- "지정 병원"과 "저장(♡)"은 로컬 저장 방식(둘 다 `SharedPreferences` id 배열)은 같지만 키(`designated_hospital_ids` vs `saved_hospital_ids`)와 화면 위치(홈 상단 vs 저장 탭)가 분리되어 있어 서로 간섭하지 않는다.
- 진료기록의 병원 필드는 `HospitalRepository.search()`를 그대로 재사용해 이름/주소로 실시간 후보를 보여준다 — 검색 로직 자체는 건드리지 않고 소비만 했다.
- 사진은 `image_picker`가 반환한 파일 경로를 그대로 저장한다(별도 영구 저장소 복사는 하지 않음) — "과하게 만들지 말 것" 지시에 맞춰 최소 구현으로 남겨 뒀다. 기기에 따라 캐시가 정리되면 사진이 사라질 수 있다는 점은 "기기에만 저장" 고지의 연장으로 봤다.
- ID는 `uuid` 패키지 없이 `타임스탬프_난수` 조합으로 생성한다(로컬 전용 데이터라 충돌 가능성이 실질적으로 없음).
